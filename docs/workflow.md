# 초기 기능 구현용 워크플로우

## 요약 (개발할 때 볼 내용)

- [개발 플로우](#개발 플로우) 보시면 됩니다

---

## 개요

초기 기능 구현 (~6월) 을 위해 GitHub Issues 기능을 기반으로 한 워크플로우를 사용한다.

## 용어

1. 기능: 기능 명세서 상에서, 큰 기능의 카테고리 e.g. "사용자"
2. 세부 기능: 기능 명세서 상에서, 기능의 하위 항목 e.g. "사용자 - 회원가입"

## 상세

관리하는 항목은 크게 두 카테고리로 나뉜다.

1. 전체 기능의 진행 상황
   - 전체 진행도
   - 각 세부 기능별 퍼블리싱, 백엔드 구현 여부, 연동 여부 등
2. 팀원별 구현 태스크 (팀원 한 명이 범위를 정하여 작업하는 것)

두 카테고리를 모두 GitHub Issues로 관리하되,
(1)을 (2)에서 참조하는 방식으로 구현 상황과 기능 진행 상황 간의
연동성을 높인다.

### 구성 요소

1. '초기 기능 구현' Milestone: 전체 기능 완료 유무를 트래킹한다.
2. 기능 하나당 Issue 하나를 두고, 해당 기능의 구현이 완료되면 닫는다.
3. 세부 기능들은 각각 상위 기능의 Subissue로 관리한다.
   - 진행 요소의 완료 여부를 label로 관리한다:
     - 프론트 진행 요소: `프론트: 퍼블리싱 완료`, `프론트: API 연동 완료`
     - 백엔드 진행 요소: `백엔드: API 작성 완료`, `백엔드: 구현 완료`
   - 진행 요소 하나가 달성될 때마다 해당 label을 달아준다.
   - label이 모두 달리면, 기능 구현이 완료되었다는 뜻이다.
     따라서 Issue를 닫는다 (자동화되어 있다).
4. 구현 태스크 하나당 Issue 하나를 둔다.
   - `구현` label을 단다.

### 개발 플로우

1. 구현해야 할 세부 기능의 Issue 찾기: label 이용

2. 구현용 Issue 생성 ([예시](https://github.com/mind-seed/mindseed/issues/8)):
   1. `구현` label 추가
   2. 구현 범위 명시
   3. 관련된 기능 Issue들 모두 멘션
3. 구현 완료 시 (PR merge 후 구현 이슈도 닫혔을 경우):
   - 멘션된 기능 Issue들에 진행 요소 label 추가

4. 기능 Issue에 위 3개 label이 모두 달릴 경우, 해당 기능 구현이 완료되었다는 뜻이므로
   Issue 닫음 (자동화)
